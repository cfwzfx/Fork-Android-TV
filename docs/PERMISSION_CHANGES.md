# 文件访问与相机权限调整说明

记录日期：2026-10-13。

## 为什么修改

希望应用尽量只处理自身数据，减少访问共享文件和调用相机的能力。本次优先移除 `MANAGE_EXTERNAL_STORAGE`（所有文件访问）和 `CAMERA`（相机），接受依赖这些权限的功能暂时不可用，不扩大改造范围。

所有文件访问权限可用于广泛读写共享存储，包括其他软件保存到共享目录的文件；它并不意味着能够读取其他应用的内部私有数据库。

## 修改前后

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 所有文件访问 | 手机端、TV 端均声明；统一文件权限入口在 Android 11 及以上尝试申请 | 从最终清单中移除；Android 11 及以上调用该入口时提示“当前功能未开放”，不申请权限、不继续执行后续操作 |
| 相机与扫码 | 手机端声明相机权限，扫码页面初始化摄像头并识别二维码 | 从最终清单中移除；扫码入口保留，进入后提示“当前功能未开放”并返回 |

主 Manifest 使用 `tools:node="remove"`，防止依赖库再次合入这两个权限。这些移除标记不是实际申请权限；同时删除了所有文件访问设置页的查询声明及对应申请逻辑。

## 有什么影响

- 二维码扫码不可用，包括使用扫码配对的投屏、同步入口；本次没有移除局域网发现能力。
- Android 11 及以上，经过 `PermissionUtil.requestFile()` 的本地文件浏览、本地配置加载、备份和恢复等操作会被拦截。
- 从其他应用通过 `ACTION_VIEW` 打开的内容也经过这一入口，因此相关文件或链接打开操作同样可能被拦截，不能只理解为关闭了文件浏览器。
- 应用内部视频缓存使用 `filesDir/offline_media`，不依赖这两个权限；本次未修改缓存下载、管理和播放逻辑。
- 没有逐一改造其他直接访问共享路径的代码，也没有保证所有外部文件操作都能优雅降级；未经过统一入口的操作仍可能失败。

## 保留的范围与验证

旧版存储权限仍保留：`READ_EXTERNAL_STORAGE` 的 `maxSdkVersion` 为 32，`WRITE_EXTERNAL_STORAGE` 为 29。Android 16 及以上不会因这两个声明获得授权，但 APK 清单中仍可看到声明，旧系统上仍可能生效。其他应用查询代码及其余权限也未调整，因此本次不是完整的外部数据访问隔离改造。

手机端和 TV 端 Debug 构建通过；检查两端 Debug、Release 合并清单，确认均不包含 `MANAGE_EXTERNAL_STORAGE` 和 `CAMERA`。未运行设备界面测试，也未提交或合并代码。

相关实现：`app/src/main/AndroidManifest.xml`、`app/src/mobile/AndroidManifest.xml`、`PermissionUtil.java` 和 `ScanActivity.java`。
